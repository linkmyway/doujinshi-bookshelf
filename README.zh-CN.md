# 同人书架 — 个人收藏书架

个人同人志收藏书架的实现方法开源版：作者分区书架、封面网格、内置阅读器与推荐收件箱是怎么做出来的。

- 实现文档：[`docs/IMPLEMENTATION.md`](docs/IMPLEMENTATION.md)（架构、数据模型、阅读器故障转移、两层推荐制、强制产品规则）
- 参考代码：[`reference/`](reference/)（数据模型、会话锁定的两级故障转移阅读器、两层候选裁决；`npm install && npm run typecheck` 可直接验）
- 本仓只有方法与脱敏说明；真实藏书数据、封面与个人信息不在本仓（存放在私有存档仓）

一个为个人同人志收藏而做的网页应用：按作者分区的书架、逐条核验过的来源链接、带双源故障转移链的站内阅读器，以及一个推荐收件箱——新发现先在那里等所有者点「留下/不要」，才准上架。

本仓开源的是**实现方法**：架构、数据模型，以及让这套策展可信的运营规约。所有者的藏书数据**不在本仓**（存放在私有存档仓）；下文的示例结构仅作示意。

## 功能

- **按作者分区**：系列按卷序成组，分区内以核验过的发布日期（奥付日期，永不按上传日期）从新到旧。
- **卡片纪律**：卡片只显示策展人定义的一小套 tag，其余都是元数据，不是装饰。
- **只收核验过的链接**：每条链接入库前都经源站 API 核对，未核验不上架。
- **站内阅读器**：两级故障转移（一级图库源 → 镜像源），按书、按会话锁定，一次阅读不会在源之间来回跳。
- **推荐收件箱**：首页两层候选条——A 层「全门槛通过」，B 层「硬规矩全过、附一条写明的存疑点」；候选不过期，等所有者裁决；裁决结果回喂筛选过滤器当训练样本。
- **故意不做应用内管理 UI**：目录变更只经策展代理执行的服务端动作。

## 设计

- 浅紫配色（定版，书架永不暗色化）、封面网格里的 CSS 3D 书本、移动端优先（每行 3 本）、作者目录用底部弹层。
- 刻进实现的移动端教训：不用 View Transitions（曾冻结所有者的 WebView）；沙箱探针永远代替不了所有者的真机裁决。

数据模型、服务端动作面、阅读器/故障转移设计、候选收件箱与运营规约（亲验纪律、不擅自下架、每周五件套备份）见 [`docs/IMPLEMENTATION.md`](docs/IMPLEMENTATION.md)。
